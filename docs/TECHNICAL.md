# 구현과 검증

ISO9660의 FBD/BASEBALL.FBD는 BNDR 디렉터리로 4,441개 항목을 관리합니다. 파일 크기·섹터·텍스처 헤더를 유지하고 원본에 주소를 지정해 적용합니다. 문장 슬롯과 레코드 경계를 검사하며 일반 문자열 검색으로 선수 능력치나 암호 테이블을 덮어쓰지 않습니다.

fixed_font.py는 BBFONT/MENU2D, BBFONTG, KFONT의 감사된 미사용 슬롯에 나눔스퀘어 네오 Bold를 넣습니다. 한글 및 고정 길이 이름의 합자 1,268개를 쓰고 나머지 글리프를 보존합니다. WBC 표시 이름은 COM_SEL.OVL의 448개 레코드를 선수 ID로 연결하며 유니폼 문자·번호와 선수 능력치는 유지합니다.

GEDATA 대사는 원래 제어 명령을 보존하고 22칸·3줄 기준으로 검수합니다. CP932의 중복 인코딩과 구조체 안의 문구도 별도 주소 검사합니다. 페넌트 티커 48개 문장은 printf 명령을 제외한 공백·문장부호를 전각으로 변환합니다.

텍스처는 CP4/CP8 및 공유 팔레트를 해석해 같은 팔레트로 재인코딩합니다. menu_textures.py, mode_textures.py, legacy_textures.py, event_picture_labels.py에 좌표와 번역이 있습니다. verify_picture_patch.py는 최종 ISO를 읽어 336개 아틀라스·867개 사각형의 예상 내용, 바깥 픽셀과 헤더 보존을 확인합니다.

validation/에는 빌드 당시 보고서를 공개합니다. runtime_verification.json은 최종 해시의 페넌트 확인과 이전 해시의 WBC 실행 확인을 구분합니다. 실행 스크린샷은 작업 폴더에 보존했으며 이 소스 저장소에는 재배포하지 않습니다. 파일 대조가 모든 플레이 분기 검증을 의미하지는 않습니다.
